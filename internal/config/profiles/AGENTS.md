# Codebase Patterns

## Profile System
- Profiles are Agentfile templates that provide pre-configured setups for different agent types
- Embedded Agentfiles use naming convention: `Agentfile.<profile-name>` (e.g., `Agentfile.claude-code`)
- Profile templates can be generated by running `agentbox init --profile <name>` which writes an Agentfile
- The claude-code profile includes: build script, network presets (anthropic, github, npm, pypi), and persistent mounts
- Other profiles (codex-cli, openhands) are stubs with minimal configuration (command + workspace only)
- Init command uses `profiles.GetEmbedded()` to retrieve and write embedded file content verbatim (no YAML generation)
- Error messages and reference template list only profile names, not descriptions

## Embed Pattern for Profile Discovery
- Use `//go:embed Agentfile.*` directive to embed all profile templates at compile time
- Profile discovery: use `fs.ReadDir()` on the embed.FS to enumerate files, then parse filenames
- Profile names are extracted by stripping the "Agentfile." prefix from filenames
- Content retrieval: use `fs.ReadFile()` on embed.FS with constructed filename "Agentfile.<name>"
- Return (content string, found bool) pattern for "found or not found" operations
- During migration periods, use temporary function names (e.g., EmbeddedNames, GetEmbedded) to avoid conflicts with existing functions

## YAML Validation
- Use Go's `gopkg.in/yaml.v3` for parsing and validating Agentfile YAML
- Config struct in internal/config package defines the expected YAML structure
- All embedded Agentfiles must parse as valid YAML without errors
